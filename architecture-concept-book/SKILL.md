# 建筑概念册：从资料到成册

把提供的资料组织成能说明设计判断、支持比较和继续修改的方案册。这里的“概念文本”包括文字、图纸、分析、表现和排版，不只是几段宣传文案。以 GIGIRI 的工作方法为经验来源，不把其地点、数量、页数、功能、尺寸、指标或审美当成新项目默认值。

## 阅读路由

- 开始任何任务：[资料与来源](references/01-intake-and-authority.md)，用户可用[资料提交表](assets/intake.md)。
- 已提供文本/视觉REF或需要锁定风格：[参考册转译](references/style-reference.md)。
- 只有用地图、需场地/周边模型或接收已有场地包：[场地交接](references/site-handoff.md)。
- 新建或重构内容：[分析与叙事](references/02-analysis-and-narrative.md)。
- 需要图纸、模型、日照或效果图：[图纸与模型表达](references/03-drawings-and-models.md)。
- 决定视觉系统或开始排版：[版式与文字](references/04-layout-and-copy.md)。
- 存在指标、功能面积或造价：[指标与估算](references/05-metrics-and-estimates.md)。
- 构建和交付前：[构建与验收](references/06-build-and-delivery.md)。
- 更新已有册子：[修订与依赖](references/07-revision-playbook.md)。
- 需要具体例子：[方法来源](references/gigiri-method.md)。需要命令行辅助：[工具说明](references/tools.md)。

只读取当前阶段需要的细节。用户已说明的要求优先；不把工作流中的可选建议变成额外审批或无关任务。

## 1. 定义任务与资料能力

先检查实际资料、版本及已有成果，不先重建工程。确认读者、阶段、交付语言、篇幅倾向、参考资料的作用和最终格式。能从文件提取的条件直接提取；只问阻塞指定能力的问题。对于非阻塞缺项，保留 unknown 并继续。

将输入分为任务/意图、用地/位置/现状、模型/图纸、指标/分析、参考册、旧稿/修改及交付/许可。参考册作为独立正式输入，读取指定页，明确哪些维度由它控制；不能因已有模型就跳过用户的文本REF。只有用地图而缺可信场地底座时，先衔接独立的site-context-model工作流；已有可靠场景直接核对接收。

首次资料核对后给出简短的“已具备 / 真正缺失 / 可先完成”。建立资料清单：文件、版本或哈希、用途、权威范围、读取结果、许可/署名。原文件只读，导出和排版进入工作区。

按能力选择范围：

| 实际输入 | 可实现 |
|---|---|
| 说明、图片、PDF | 分析已有信息、叙事、图文册、来源索引 |
| 有尺度的 CAD/可信图纸 | 对应图纸整理与可追溯尺度表达 |
| 可解析原生模型 | 原模型相机、总图、剖面及几何核对 |
| 有语义映射和统一口径 | 功能/楼层图、面积与方案比较 |
| 有坐标、真北、时区、日期及可靠计算 | 明确参数的地理/太阳分析 |

不能把模型体量视为完整 BIM，不能把原生投影称为法定指标。资料少时做真实的有限范围成册，不凑分析和假图纸。

## 2. 建立事实、观点和设计回应

为关键事实记录 `id / value / unit / status / source / locator / scheme`；区分源文件事实、计算、明确假设和未知。几何、法规、市场、户数、估算分别有自己的权威来源。

每项分析形成链条：**可核证据 → 对项目的影响 → 设计动作 → 用哪张图证明 → 尚待解决的问题**。不要只列交通、景观、功能等标题。无法证实的宣传形容词不能替代设计判断。

先写一段设计主张和三到五条有证据的回应；再组织章节。叙事可以随项目不同采用场地、生活体验、功能、构造、更新策略或方案取舍作为主线。案例说明“借鉴哪种关系、如何转译”，不把案例的服务、认证、数量或照片描述为本项目已实现。

## 3. 先做逐页计划

使用 [资料表](assets/intake.md)、[逐页表](assets/page-plan.csv) 和 [项目清单模板](assets/project-template.json)；复杂项目参考 [清单约定](references/manifest.md)。不要求普通用户手填 JSON。

每页至少明确：稳定 page ID、目的/结论、主图、支持事实、正文、图注、版式类型、资料状态。页码只是最终顺序，不作为模型或事实 ID。方案 ID 在所有图文表格中保持一致。

常见内容模块：任务与愿景、场地、设计回应、形体/方案、总图与指标、平面/剖面、功能/流线、空间体验/表现、比较、实施条件、来源。按资料和任务选用，不固定顺序、页数或每方案三页。单方案不凑多方案比较；图纸不足时不编造平面和剖面。

先排封面、一个分析页、一个方案/总图页、一个数据页等有代表性的少量页面。用户已授权完整制作时，核对代表页后继续展开，不因默认流程反复等待确认；用户明确要求先看小样时以小样为当前交付。

## 4. 做图时锁定权威

先从REF实际页面提取网格/留白、字体层级、色彩角色、文案结构、图纸表达、构图与气氛，用[风格转译表](assets/style-brief.md)记录本项目落实方式，再检查代表页。不能只写泛泛的风格形容词或移植参考项目的卖点。

原生模型负责体块、层数、洞口、退台、柱、场地、道路和邻栋位置。参考册可负责排版、表达、材质、灯光或情绪；每一项作用分别说明。编辑参考图不能改写源几何。

比较图使用统一朝向、取景策略和尺度；主体居中依据建筑投影，排除地面和周边。功能与日照同组构图保持建筑大小一致。总图保留真实边界、退线、方向、配准与可核比例尺。剖面来自真实切面并说明切线位置。

生成式效果图属于表现，不用于计量。先做原模型几何底图，再做风格转译，逐项核对轮廓、层数、凹层、柱、道路、邻栋和树位。用户新授权的立面或景观深化单独记录，不伪称原模型已经改好。视角、近景、植栽密度和灯光根据本次任务决定，不继承 GIGIRI 的具体镜头。

## 5. 指标和文字共用一个数据来源

事实表驱动总图旁指标、比较表、图注、成本和文字中的数字。修改数据时更新所有消费者，不手改一张表了事。

准确区分用地、占地、地上/地下、总建筑面积、计容面积、使用面积、功能面积和开放空间。FAR 依据已确认的计容口径；若任务约定地上建筑面积/用地面积，明确这是该册的计算口径，不能暗示当地法定口径已核准。

先按未舍入值计算，再显示格式。连续量的显示精度统一；未另定时两位小数，套数、车位、层数等计数保持整数。内部坐标与算法精度不降为显示精度。未知不写 0，假设要有显著说明。估算停车与真实布置停车区别标注；成本说明币种、时点、包含项、排除项与风险。

## 6. 构建、审阅、交付

选择可维护的源格式：已有 InDesign/PPTX/设计文件就沿用；可编程排版可使用 ReportLab、SVG 或打印 HTML；工具不足时明确交付到大纲/源稿阶段。不强迫所有项目使用同一种软件。

维护内容数据、图版、版式与最终输出之间的关联。正文保持可搜索，技术图优先矢量，嵌入允许嵌入的字体。导出最终 PDF 后重新读取页数、文本、页面尺寸与书签/链接；实际渲染全册接触表，并逐页检查必要细节和全部改动页。静态检查不能证明视觉正确。

三类结果分别报告：资料/计算核对、实际成品视觉检查、可携带与交付检查。可用 [验收记录](assets/verification-template.md)。检查必须绑定最终文件哈希，后续重建会使旧检查失效。没有打开/渲染过的文件记 `not_run`，不写“全部通过”。

默认交付约定的 PDF、可维护源文件、图版/数据、来源与假设表、简短使用说明、版本与验收摘要。只做 PDF 时不自动制作视频、网页或公开项目材料；用户明确要求时再启用相关工作流。

## 不可省略的边界

- 参考风格不能替代真实模型、场地关系和图纸证据。
- 图框文字只约束所属图框；缺层高/标高/真北不得从别处继承。
- 不用没有依据的距离、比例尺、认证、法规、造价或日照结论装饰页面。
- 不把提示词、排版代码、状态报告或哈希清单当作已经做好的册子。
- 不把本次制作授权延伸为原模型改造、外部发布、付费生成或素材再分发授权。
