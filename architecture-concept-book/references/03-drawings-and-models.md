# 图纸、模型、分析与表现

## 先区分图像角色

原生几何图说明项目本身；计算分析图说明某套输入与方法的结果；概念示意表达设计动作；生成式效果图表达材质/空间意向；案例照片说明其他项目。图注和数据记录中分别标识，不靠读者猜。

## 原生模型链条

1. 固定源版本/哈希，识别方案、建筑主体、场地和周边范围。
2. 核实单位、轴向、世界变换、图层/组/实例、场景可见性与原生相机；用户预设视角优先，直接读取SU Scenes/相机，不要求另交手工机位表。
3. 保留主体、场地、道路、邻栋、树木、洞口、柱和退台的原位关系。
4. 为每张图记录方案 ID、源哈希、原生场景或派生相机、投影、取景和排除规则。新增/调整机位标记为派生，不能悄悄替换指定镜头。
5. 出图前后做轮廓/层数/洞口/场地检查。仅改变取景，不移动模型来凑居中。

如果模型解析失败，说明具体缺失并尝试可靠导出格式或原生软件只读出图。不能换成近似盒子却称“原模型”。后补概念几何需要用户授权，且独立标记。

## 总图

由可信顶视投影/图纸得到轮廓和边界，保留源几何与实际道路。风格化可以改变笔触和色彩，不能改变地块、比例或邻栋位置。边界/退线/标注规则在同一册中统一；红色虚线与 SITE/基地标识是可选的一致表达，不是所有项目的法定制图标准。

比例尺必须由单位、投影视域、图幅和后续缩放计算。裁图或放大后同步重算；不知道尺度时省略比例尺并说明。真北与页面上方分别处理。光影是实算还是观看辅助要写清；示意树位不能伪称原生实测。

图旁指标与主图协调上下对齐，主图保有足够可读尺寸。面积表不能从颜色像素直接推导。图纸和右侧信息的边界对齐优先于单纯“填满”页面。

## 平面与剖面

平面说明对应楼层/标高、方案、切面条件和图纸阶段。复式/跃层在户数上只计一户，实际上下层建筑面积仍分别核算。交通、洞口、共享与住宅功能不能只凭颜色猜。

剖面由明确切线或剖切面取得，保留实体轮廓和真实开口。功能分色可作为图层，不能生成不存在的楼板或空间。人物和植物是尺度配景，放在实际可站立或可种植处；不穿楼板、不遮盖关键结构或标注。多方案剖面共用标高、比例和图例；不为凑整齐强改高度。

## 功能和流线

建立“源对象/面/层位 → 功能 → 颜色/编号”的映射表。功能图例全册一致；装饰主题色与语义色分开。开放走道、玻璃围护的空洞和架空空间不能当实体面积，设备与核心筒不能当住宅。

有未分配或待核部分时保留独立类别。功能图的面积、户数及文字读取同一数据。流线要区分公共/住宅/服务/消防等适用系统，并说明未完成的通达验证；一个箭头不等于已经做完消防或无障碍设计。

## 日照与其他性能

记录地点、纬经度、真北、时区、日期、时间步长、遮挡物范围、接收对象和统计口径。即时受光比例、某时刻累计小时、全日累计、季节平均、户均和立面采样平均不能混用。没有法定方法验证时称设计研究或潜力，不称合规证明。

模型若变更楼层、受光面、住宅分配或周边，相关分析失效。不能复用旧方案的分数。比较视图保持同构图和可读尺度；不通过统一染色掩盖无结果区域。

## 效果图与风格迁移

先把参考的作用分为建筑风格/颜色、阳台节点、灯光、视角、构图、气氛、版式与文字。用户只指定某些作用时不扩大授权。

先出原模型底图，再把该底图作为几何和相机权威，参考图作为风格权威。若要求场景一致，底图要包含原位道路、邻栋、树与场地，不能只出孤立建筑后让 AI 随机补环境。换机位避开遮挡，不删邻栋。两点透视需竖直线平行；不能拿轴测图代替。

具体提示顺序：目标建筑与用途 → 目标相机 → 必须保留的体块/层位/开口 → 允许的立面解释 → 材料 → 原位场景 → 光线/景深 → 禁止改动。已确认的前景虚化只影响已有前景和授权的植栽，不模糊主体来掩盖错误。

生成后逐项对比：总轮廓、前后翼宽度、每个层位、退台数、水平凹层、柱、洞口、裙房、道路转折、邻栋轮廓和树位。好看但缺层、封洞、移路的图应退回。新增立面或景观属于本轮表现/设计意向，不表示原模型已修改。表现图不回流为计量几何。

## 跨页一致性

同一方案的原生几何、总图、剖面、功能图、日照与表现相互核对。允许不同镜头，但不能出现某页有洞口、另一页被填平的矛盾。记录图版版本，模型更新后查全部消费者。
