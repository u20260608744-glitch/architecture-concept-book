# 指标、口径与估算

## 一个事实表，多处显示

每个指标绑定方案、源文件/对象/表格、单位、状态、口径与计算过程。总图旁指标、功能图、比较表、图注、成本和正文中的数字引用同一事实 ID。内部存未舍入值，显示时再格式化。源变更后，旧结果必须重新计算或明确标为未更新。

## 不同面积不能混用

| 名称 | 需要说明 |
|---|---|
| 用地面积 | 测绘/地籍/模型哪一种边界，是否已核准 |
| 占地/建筑基底 | 何种投影、雨篷/架空/裙房如何处理 |
| 地上建筑面积 | 已确认的面积计入和排除规则 |
| 地下建筑面积 | 实际模型、设计图还是估算层面积×层数 |
| 总建筑面积 | 包含哪些地上/地下及特殊面积 |
| 计容面积 | 对应地区与规则，有何豁免/折算 |
| 使用/套内/可售面积 | 各自边界，不等同 GFA |
| 功能面积 | 是否含走道、墙体、开放区和待分配区 |
| 绿地/屋顶绿化 | 地面绿地与屋顶/平台种植分别统计 |

一般表达式：

```text
FAR = 已确认的计容面积 / 用地面积
建筑密度(%) = 已确认的建筑基底面积 / 用地面积 × 100
地面绿地率(%) = 对应口径的地面绿地面积 / 用地面积 × 100
功能占比(%) = 该功能面积 / 明确的统计分母 × 100
```

用户若指定概念阶段以地上建筑面积/用地面积计算 FAR，按要求执行并写明口径。只有该口径得到当地规则支持时才称法定 FAR。不要把“Model floor/site ratio”当不需要解释的通用术语。

计量优先实际水平板或已确认平面；开洞、挑空、玻璃围护内的无板空间不能当实体面积。架空、有盖开放和设备空间依据项目规则单列。不能从体积/标准层高倒算所有建筑面积，也不能用模型表皮面积替代楼面面积。

## 数量和户型

复式上下层计建筑面积时分别核算，户数只计同一住宅一次。走道分割、单元边界和住宅分配都需要依据；颜色或一个体块不自动等于一户。未分配的附加空间保留其面积，但不凭空增加户数或日照接收对象。

检查分项与合计：功能面积合计与分母，产品户数合计与总户数，地上+地下与总建面。差异如果来自不同口径，解释差异而不是强行调数配平。

## 显示精度

项目要求优先。未另定时，面积、比例、时长、长度和 FAR 等连续量显示两位小数；车位、住宅套数、层数等不可分计数保持整数。范围的两端遵守同样精度。时间刻度可保持实际时制，不把 12:00 写成 12.00 小时。

不把计算坐标、网格、源几何和太阳算法降到两位小数。只在呈现层舍入；用显示值相加造成的末位误差应和真正计算错误区分。未知为 null/待核；真实零才是 0。

## 停车

区分需求、估算供给和已布置车位。需求来自适用标准或明确假设；估算供给说明毛面积/效率/单位面积与层数，不能声称已解决坡道、柱网、消防、设备和无障碍。每层面积与地下层数需要来源；边界内退不能自动代表可开挖、可支护或合法地下退线。

## 概念成本

记录币种、计价时点、计价来源、面积口径、各分项单价、场地费、预备费与浮动区间。区分地上/地下、立面档次和专项费用。

```text
概念费用 = (地上计价面积×对应单价 + 地下计价面积×对应单价
          + 已明示的场地及专项费用) × (1 + 对应预备费率)
```

这是可配置示例，不能硬设所有项目都按此公式。深基坑、降水、支护、基础、机电、税费、融资和当地市场条件是否包含需分别说明。±区间不代表未计价风险已覆盖。基准单价过期或不适用时不要冒充最新报价。

## 最终数字检查

逐项复算公式、分母、单位与合计；再到最终 PDF 的文字和表格中核对。不能只验 JSON，而 PDF 仍显示旧术语或旧精度。模型版本、指标版本和成册版本需要绑定；网页或旁白若一并交付，也纳入同一次数字更新。
