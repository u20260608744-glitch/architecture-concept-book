# 构建、成品验收与交付

## 选择可维护的制作路径

沿用项目已有可编辑文件和工具。可以是 PPTX、InDesign、其他设计文档、可编程 PDF 或打印 HTML。选择依据：使用者是否能继续修改、图纸与文字是否清晰、批量更新是否稳定、工具是否真实可用。不要把所有来源图纸拍成一张低分辨率截图后当可编辑成品。

内容数据、图版文件、版式规则和导出结果分开。大项目维护逐页清单与图版来源，小项目可以用简单表格；不为简单任务引入数据库或服务。

## 构建顺序

1. 冻结本次输入版本、事实表和适用口径。
2. 生成/整理当前图版，保留其源哈希和相机/分析参数。
3. 排代表页，解决字重、字号、边距、图纸比例和长文本。
4. 展开全册，建立稳定 page ID 到实际页序的映射。
5. 导出 PDF 与约定的可维护源文件；补目录、书签、来源与假设。
6. 在输出位置重新读取与渲染最终文件；修复后重建、重检。

文档工具若有环境自身的导出/作者操作约定，按该环境要求执行；不要将特定本机路径写成公共 Skill 的前提。

## 三类检查分别记录

### 内容与来源

确认项目/方案 ID、章节、语言、图注与页序；逐项查事实来源、假设与 unknown；检查案例图未冒充本项目。若新增方案，所有总览、功能图、指标、正文和引用都更新。正文数字与事实表一致，不能只改数据文件。

### 几何与计算

核对建筑轮廓、各层位、退台、柱、洞口、场地和周边；图纸比例与相机条件可追溯。复算面积、分项、分母、户数、密度、FAR、日照统计和成本。物理算法/法规结论需要独立的输入与方法验证，版式校验不能代替。

### 实际成品视觉

渲染最终 PDF 的每一页接触表，检查整册节奏、漏页、重复和明显异常；在可读尺寸查看每一页的文字/表格/图例和技术细节。可按复杂度分批检查，但所有改动页、数据页与代表图纸页必须完整查看，不只看封面。

检查字缺/乱码、字体嵌入与授权、断行、重叠、溢出、图像拉伸或错误裁切、表格与图例、页脚和边界白边。跨页检查标题位置、图框底线、模型尺度与色彩语义。

接触表能发现构图问题，但不能证明小字正确；文本提取能核对数字，但不能证明没有重叠。两者缺一不可。

## 最终文件绑定

记录最终 PDF、可编辑文件和关键图版的 SHA256。视觉观察与检查报告写入目标文件哈希、实际检查范围、观察结果和未执行项。检查后任何重导出、换图、页序或字体变化都会让对应报告失效。

允许 `pass / fail / not_run / not_applicable`。`not_applicable` 要说明原因；不能用它掩盖任务要求但未做的检查。自动脚本只能验证其实际检查的条件，不能自动写“人工已看过”或“全部视觉合格”。

## 可携带与交付

交付目录一般包括：

```text
final.pdf                 约定的最终册子
source/                   可维护排版源与必要配置
figures/                  有分发权限的当前图版
data/                     事实、文案、页面与来源表
README                    打开、修改、重新导出的方法
checksums.json            最终文件校验
verification.md           检查范围、结论、未核和未执行项
```

不必把全部临时文件和第三方原件塞进包。源文件如果依赖本机绝对路径，改为相对路径或说明如何重新绑定，授权范围允许时包含必要资源。禁止在交付包中放账号、密钥和未授权素材。

若用户同时要求交互 HTML，则另外构建和测试该成品的章节、模型操作、原册、语言、移动端和离线；PDF 检查通过不表示网页也通过。视频、模型修改和网站发布也分别验收。

## 停止与继续的条件

修复实际发现的问题，重新检查受影响部分。要求已满足且检查通过时直接交付，不无限扩大测试数量。缺失工具或数据阻塞某项能力时，交付已完成部分并准确列明限制；不能把提示词、代码或预备稿称为已经导出的成品。
