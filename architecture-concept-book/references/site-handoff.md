# 接收场地 Skill 的成果

当任务从“只有用地图”开始时，先用独立的 [site-context-model](https://github.com/u20260608744-glitch/site-context-model) 完成位置核实、卫星/边界配准、场地和周边模型。它不要求本 Skill 已安装；本 Skill 也可接收人工或其他软件制作的等价成果。

## 接收什么

接收 `site-handoff.json` 或同等可读记录，以及实际文件：位置核对材料、原影像/许可、标注卫星图、边界矢量、CAD/DXF、原生场景模型、来源/估计清单和检查截图。只有本次确实要求并完成的文件才标完成。

逐项核对：

1. 文件存在，版本和 SHA256 匹配；路径相对于交接目录，不依赖制作机器。
2. 地点、边界来源/精度状态、图形面积与文件声明面积分开；位置和地籍精度未知不写成通过。
3. CRS、单位、坐标原点、轴向、真北、垂直基准与模型变换可解释；已有配准/模型卫星面沿用，不重新凭视觉拟合。
4. 场景对象范围、图层、道路/建筑/植栽来源、高度的测量/估计/未知状态明确。
5. 裁切范围、标注风格、边界线型/颜色及透明度一致；不同专题地图复用同一真实边界，不徒手画出互不一致的红线。
6. 只要求背景时，交接的基地不夹带其他旧方案；方案与环境明确分组。

## 进入成册数据链

为每项交接文件登记稳定 source ID，绑定图版、页面和事实。已经配准的栅格/模型以原坐标与变换为准；绘图缩放裁切不改变边界几何，比例尺随最终图幅重算。来源署名留在地图上或可访问图注中。

交通、配套、邻栋高度、景观与太阳分析各自声明范围、日期和方法。场地模型中的估计高度会影响遮挡和天际线，因此相关结论必须继承估计条件。缺高程就不写坡度/排水结论，未知产权精度就不冒充地籍测量。

交接不合格时，只退回受影响项；可继续章节、文案、风格与不依赖该项的图版。不要为了排版方便重画、移动或旋转建筑/道路来掩盖配准问题。
