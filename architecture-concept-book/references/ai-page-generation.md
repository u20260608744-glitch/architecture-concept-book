# SU白模型 + 预设视角 + REF：AI逐页生成全册

## 案例的真实分工

项目所有者明确说明：GIGIRI案例提供给AI的是自己建好的SU白模型、已设定的视角和参考文本，概念册/PPT每一页由AI生成。因此不要把效果图、分析图、完整文案、指标表、逐页稿和排版误列成用户必须先准备的输入；它们通常是AI应完成的工作。

“AI生成每页”指AI组织并执行从资料到成册的全过程，不表示原SU方案体块由AI设计，也不表示每种技术图和数值都由图像模型凭空生成。

## 三类核心输入如何读取

| 输入 | 应直接读取 | 不应让用户重复做 |
|---|---|---|
| SU白模型/等价原生模型 | 组/图层、层级变换、场地与方案、单位、可见性和可解析几何 | 不要求先画全套排版图或手填所有可提取指标 |
| 预设机位 | SU Scenes/相机的眼点、目标、Up、投影、视角、可见对象；必要时对照导出JPG | SU内已有机位时，不要求另交每个镜头的完整数字表 |
| 参考文本REF | 实际页幅、网格、字体层级、图文节奏、文字逻辑、图纸/建筑表达 | 不要求用户先把REF人工整理成设计系统 |

模型中已有可信场地与周边时沿用；缺场地底座且任务需要时衔接独立场地Skill，不无故重做已有环境。用户补充的明确要求直接进入本次任务约束。

## AI的逐页生产责任

1. **读模型与REF**：固定版本；提取可用几何、原生相机和参考风格，指出真正影响准确性的缺项。
2. **组织内容**：由项目事实写设计主张、分析、章节、逐页目的、正文和图注；不是要求用户先交完整稿。
3. **生成图版**：从模型导出同机位底图、总图/平剖面等能被几何支持的图；按参考制作表现与分析表达。
4. **计算和验证**：面积、日照等用适当确定性工具和已知参数计算，记录来源与假设；不把LLM猜值或彩色效果图当测量。
5. **完成每一页**：AI将主图、辅助图、标题、正文、图注、表格、页码和来源组成页面，统一整册视觉与语气。
6. **成册与检查**：按用户指定生成PPTX/PDF和可维护源；实际打开/渲染最终文件。PPTX需要可编辑或其他要求时依任务验证，不用一组PNG冒充已完成PPTX。

## 机位与几何约束

优先使用用户预设机位，保留相机、投影与可见性；在同视角上进行获准的风格表达。新增总图/分析机位或必要裁切单独标记为AI派生，不能默默替换用户指定视角，也不能移动模型凑构图。

表现图可以按授权REF深化材质、阳台、灯光和气氛；体块、洞口、层数、道路、邻栋等仍要与输入核对。需要本次设计修改时明确记录，而不是假装源模型已经改变。

## 什么时候才需要补充输入

从模型和参考能直接读到的内容不补问。只有缺失且不能可靠推导的事实才局部补充：例如功能归属、户型/走道规则、法定计容口径、无法确定的真北/地点。可继续其他页面，不把一个局部未知变成要求用户先做好整套分析。

## 案例展示规范

公开示例分成“用户输入”和“AI产出”：展示原始SU/机位图，说明REF作用；再展示AI生成的完整页面。标明图像角色、源版本和页码，不把成品页当成用户预先提供的资料，不把用户模型说成AI创建。案例图必须来自实际成果，不以虚构示意替代用户要求展示的项目。
