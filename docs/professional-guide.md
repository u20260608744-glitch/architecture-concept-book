# 使用与功能详解

## 这套 Skill 解决什么

概念册的难点不只是排版：资料可能有不同日期，模型和数字可能不同步，图像可能好看却不能支持结论，单页正确也可能跨页矛盾。本 Skill 把资料、设计论证、图版和成品检查组织成一条可继续修改的生产流程。

它适用于从零制作，也适用于旧册改版、增减方案、模型替换、指标更新、翻译和版式修订。住宅、办公、商业、公建、室内、景观、城市设计和作品集可以共用方法，但分析项目、指标体系和图纸需求应分别确定。

## 三类输入，AI负责逐页生成

GIGIRI案例由用户提供SU白模型、预设视角和参考文本；每一页PPT/概念册由AI生成。用户并没有先制作好效果图、分析、完整文案或版式再让AI摆放。该分工应作为复现路径：用户交原始模型/机位/REF，AI读取、提取与计算、出图、写内容、逐页排版、成册和验证。

见[AI逐页生成流程](../architecture-concept-book/references/ai-page-generation.md)。既有CAD、指标、照片和旧稿属于可选补充，缺少不会自动阻塞全册；模型无法给出的关键事实局部待核或补问。

## 完整功能与产物

| 阶段 | 具体工作 | 可检查的产物 |
|---|---|---|
| 任务定义 | 读者、用途、阶段、语言、风格、输出格式、资料权威 | 任务摘要、能力表 |
| 资料核查 | 版本、内容、单位、坐标、缺项、来源与许可 | 输入清单、问题记录、源哈希 |
| 分析 | 从证据判断对设计的影响，选择适用分析 | 分析卡、引用与参数 |
| 设计叙事 | 提炼主张和空间动作，避免空泛口号 | 章节提纲、逐页文案 |
| 页面策划 | 每页一个目的，绑定事实和主图 | 稳定 page ID 与页面清单 |
| 模型与图纸 | 原生相机、总图、平剖面、功能与流线、比较视图 | 图版、几何来源和相机记录 |
| 表现深化 | 将授权参考用于材质、立面、景观与光影，核对几何 | 经过对照的效果意向图 |
| 指标 | 面积、比例、数量、功能分项、估算条件 | 同一数据来源、计算和解释 |
| 视觉系统 | 网格、字体、标题、图注、色彩、图框 | 代表页、版式约定 |
| 成册 | 组件排版、可搜索正文、图版导入、目录和页码 | 可维护源文件、PDF |
| 验证 | 数值与来源、逐页视觉、最终文件可用性 | 哈希绑定的核对记录 |
| 后续更新 | 识别变更依赖，重建受影响图文并复核 | 变更表、新版交付 |

## 需要哪些资料

最少是一份可读取资料和明确展示目标。模型、测绘、位置、法规或面积表不是所有册子的前提，但缺少它们会限制对应能力。资料提交流程见 [输入与来源](../architecture-concept-book/references/01-intake-and-authority.md)。

提供资料时可这样组织；不必为了匹配目录重新移动原始文件：

```text
project/
  inputs/       项目说明、图纸、模型、照片、参考资料的只读副本
  data/         事实、计算、逐页正文、项目清单
  figures/      原生导出、分析、表现和图纸
  source/       可维护的排版文件或生成代码
  output/       当前最终 PDF 和交付文件
  qa/           渲染、核对记录、版本和变更表
```

精确图纸要求尺度、单位和来源可靠。太阳分析还需要真北、地点、日期、时区和方法。缺某种条件时，先完成其他内容，不把视觉猜测当作数据。

## 使用方式

### 从零开始

```text
请使用 $architecture-concept-book。
资料见我提供的文件夹。面向业主，做一本中文概念方案册，
需要设计逻辑、场地分析、方案表达和比较，最终交付 PDF 与源文件。
请先读资料，给出能力与缺项，再建立章节和逐页计划后制作。
参考册只用于版式与表达；不要沿用它的项目事实。
```

### 先做代表页

```text
请使用 $architecture-concept-book，先做一个分析页、一个总图页和一个空间表现页。
先看排版和图文逻辑，当前阶段暂不展开全册。
```

### 更新模型或增加方案

```text
请使用 $architecture-concept-book，以新模型为本次几何依据更新现有册子。
检查受影响的总图、平剖面、功能图、表现、面积表、成本及正文。
保留已确认的风格和无关内容，列出仍需确认的指标，不沿用旧方案数字。
```

### 只有图片与旧 PDF

```text
请使用 $architecture-concept-book，基于已提供图片和旧 PDF 重构一本方案册。
可以整理已有文字、图片和图纸；没有原模型支持的部分不要补画成精确技术图。
```

### 换成其他项目类型

```text
请使用 $architecture-concept-book，为这个室内改造项目制作概念册。
以现状问题、动线、功能、材料、灯光与空间体验组织内容。
没有多方案，不需要住宅套数、停车和城市尺度日照章节。
```

## 工具条件和能力边界

Skill 本身是指导 AI 组织工作的文件。完整成册需要所在环境支持读取项目文件、生成可维护排版文件、导出 PDF 并渲染检查。原生模型导出、图像生成、地图查询等还各自依赖对应软件或工具。

配套 Python 工具只做三个确定性任务：资料清点、项目清单校验、PDF 文本摘要与逐页渲染。它不自动解读 SKP/DWG，不自动做建筑设计，也不自动把 JSON 变成完整方案册。无命令行环境时，可以人工按同一清单执行。

图像生成能力用于表现，不是测量工具。生成图若改变楼层、洞口、道路或邻栋位置，应退回修改。图纸提取、草图、效果图、分析图和参考照片需要清楚区分。

## 文本REF不是装饰

用户提供参考册时，把它纳入正式输入：阅读整册节奏和指定代表页，提取页幅、网格、留白、字体层级、图文比例、标题/正文/图注逻辑、图纸语言、镜头、材质与气氛，再用本项目事实重写内容。不能只沿用一个颜色或通用“高级”形容词。

[参考册转译流程](../architecture-concept-book/references/style-reference.md)和[转译表](../architecture-concept-book/assets/style-brief.md)用于记录每个维度的观察与落实。用户只授权版式时不扩展为建筑改造；授权材质、阳台和灯光时仍用当前模型锁住体块、道路、邻栋和现状场景。

## 从用地图到概念册

独立的[site-context-model](https://github.com/u20260608744-glitch/site-context-model)先处理位置、影像、边界和场景。通过[场地交接](../architecture-concept-book/references/site-handoff.md)接收实际图像、边界、CAD/原生模型、坐标与来源，绑定进本册的source ID。任务同时授权两项时可连续执行；不能把一本PDF当成用户所要的SKP场景，也不能把场景模型当成已完成概念册。

## 内容如何适配

不要把每个项目都写成“场地—住宅产品—六方案—成本”的固定套路。室内可先讲现状和生活路径；景观可讲水、地形、生态与使用；更新项目要讲保留、拆改和施工条件；作品集要交代个人角色与设计贡献。方案数量、篇幅、语言和审美按实际任务决定。

参考册的作用先拆成排版、文字组织、图纸表达、材料/立面、灯光和视角。用户只授权排版参考时，不自动深化建筑；用户授权立面风格时，仍保留已确认体块与场地。

## 排版和数字的关键做法

- 正文围绕证据和设计动作写，不用大量“高端、赋能、地标”等词替代空间说明。
- 先做几页不同类型的代表页，核对字体、图纸大小、空白和阅读顺序，再扩展。
- 同一比较组共用视角策略、尺寸与行轨道，方案多时分组分页。
- 数字只在一处维护；总图旁指标、比较表、图注、成本和正文读取同一数据。
- 连续量与整数计数分别格式化；坐标、面积计算和舍入显示分离。
- 在最终 PDF 上检查，不把源程序未报错当作成品正确。

## 交付什么才算完成

按约定提供最终册子及可维护源文件。来源表、假设和未核问题、图版清单、版本说明与简短验收结果随交付保留。必须读过最终 PDF 的页数和文字，实际渲染并检查图文，核对数字消费者，确认交付目录中的文件就是已检查版本。

自动检查报告与人工视觉观察分开。检查后重新导出或换图，先前的视觉报告就不再代表新版。缺工具、未查看页面或没有进行某种验证时，明确写未执行。

## 与 GIGIRI 的关系

本包提炼了该项目“资料 → 场地 → 产品/设计回应 → 方案 → 总图 → 功能与日照 → 指标与取舍 → 成册 → 修订”的方法。实际旧册作为只读经验来源；它不是一个对所有项目都正确的标准。历史版本里保留过的旧术语、不同精度或未核内容，应通过新项目的统一规则修正，而不是作为模板复制。

具体提炼见 [GIGIRI 方法说明](../architecture-concept-book/references/gigiri-method.md)。方法与练习使用原创文字和虚构示例；公开仓库另按项目所有者明确要求展示部分GIGIRI实际成果页。完整模型、完整PDF和第三方参考册不随包公开。
