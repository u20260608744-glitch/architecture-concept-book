# 做这类概念册，需要提供什么

这份表按 GIGIRI「林界叠居」的工作类型展开，让第一次使用的人知道准备哪些文件。**不是让你先把所有分析做完。** 你提供现有原始资料，AI 负责读取、分类、发现缺项和组织制作。能从文件里读到的内容不再要求手填；暂时没有的资料写“没有 / 待核”。

## 复现GIGIRI案例：只先准备三类核心资料

| 核心输入 | 用户提供什么 | AI负责什么 |
|---|---|---|
| SU白模型 | 已建好的体块/场地模型 `.skp`，采用版本 | 读取几何、组织图层与方案、出原模型图版和可支持的分析 |
| 预设视角 | SU中保存的Scenes/相机，或已有同机位JPG | 读取机位、保留构图与可见性，在该基础上制作图像 |
| 参考文本REF | 目标概念册/PPT/PDF，以及希望参考哪些方面 | 提取版式、字体层级、文字逻辑、图纸表达和视觉风格 |

**用户确认：本案例每一页都是AI生成。** 用户不需要先交效果图、分析图、完整文字、指标表和排好的页面。AI应读取现有输入，提取/获取/计算有依据的内容，完成整册；只对真正无法推导的关键事实局部补问。

下面A–F是按类型细分的**可选与条件性资料说明**，用于知道“有的话该给什么、缺少会限制什么”，不是要求全部备齐才开始。特别是指标、图纸、分析成果可由AI根据可靠输入生成，不应把输出反过来变成用户作业。

## 先选择起点

| 你目前有什么 | 能从哪一步开始 | 还不能承诺什么 |
|---|---|---|
| 只有用地图、地名和设计要求 | 用配套场地 Skill 定位、核边界、准备卫星图和周边模型；同时拟定册子主线 | 不能直接交付精确建筑平面或真实方案指标 |
| 有SU白模型、机位和REF，没有成册图文 | 资料核对 → 分析与设计叙事 → 原模型图版 → 排版与验收 | 未说明的功能、户数、法定口径不能从体块猜 |
| 有旧册和新模型 | 保留确认的风格，更新受影响图文、指标与比较 | 旧册数字不自动适用于新模型 |
| 只有图片、说明和参考册 | 可做图文叙事、已有图纸整理和概念表达 | 没有尺度就不补成可计量图纸 |

## A. 项目任务与交付条件

| 输入类型 | 建议提供的具体内容 | 文件形式 | 用来做什么；缺少时怎么处理 |
|---|---|---|---|
| 设计任务书 | 项目类型、使用人群、功能、容量、阶段、设计目标、已确定限制 | DOCX / PDF / TXT / 对话 | 建立设计问题与章节主线；不明确的约束列待核 |
| 业主/设计师意图 | 希望突出什么、已有决定、可调整与不可调整部分、上一轮修改意见 | 文字 / 录音转写 / 标注图 | 区分本次是成册、设计深化还是模型修改 |
| 阅读对象 | 业主决策、投资比较、内部评审、报批前讨论、作品集等 | 一段话 | 决定正文深度、技术程度和图纸顺序 |
| 成品规格 | 中文/英文/双语，屏幕/印刷，单页/跨页，页幅，篇幅倾向，PDF及可编辑源格式 | 一段话 / 旧文件 | 选择版式与工具；页数按内容决定 |
| 使用与署名 | 公开/内部，客户保密，图像许可，作者/团队署名，品牌素材可用范围 | 说明 / 授权文件 | 决定哪些素材能进入最终册或公开预览 |

## B. 用地、位置与现状

| 输入类型 | 需要看到的细节 | 文件形式 | 支持的工作；缺项影响 |
|---|---|---|---|
| 用地/产权测量图 | 完整图纸、图号、地块号、边长、面积、道路、北向、坐标、比例尺、图例；不要只裁红线局部 | 原 PDF / 清晰扫描 / DWG / DXF | 定位线索、边界与尺度核对；无坐标图不能直接认定绝对位置 |
| 已知位置 | 国家、城市、片区、地址、经纬度、地图链接、地块号、相邻地标，知道多少给多少 | 文字 / 链接 / KML / GeoJSON | 缩小检索范围，交叉验证定位；位置不确定时不继续声称已精确建模 |
| 卫星/航片 | 原始文件、获取来源、日期、分辨率、版权信息；有坐标/世界文件一并提供 | GeoTIFF / TIFF+TFW / PNG / JPG | 基底、路网与树冠识别；截图可作线索，不能伪装正射测绘 |
| 现状照片 | 入口、道路、邻栋、围墙、地形、树木；尽量注明拍摄点、朝向和日期 | JPG / PNG / 视频关键帧 | 核实地图变化、层数与空间体验；照片中的估计要标明 |
| 地形与高程 | 等高线、测量点、DEM、标高基准、单位与测绘日期 | CAD / CSV / GeoTIFF / 地形模型 | 地形、坡度和高差；没有高程就只做平面或明确的平基准模型 |
| 周边空间范围 | 需要精确到哪一圈、背景到哪里；道路、建筑、景观和高度的要求 | 文字 / 范围图 | 按项目需要确定范围，不把 500 m 或 1 km 作为所有项目默认值 |

没有场地模型时，先使用 [site-context-model](https://github.com/u20260608744-glitch/site-context-model)。它负责定位、配准、边界、道路、建筑和景观模型，再用交接文件把来源与坐标带入本 Skill。已有可信场地模型可直接接收，不必重做。

## C. 当前方案模型、机位与可选补充图纸

| 输入类型 | 请一起说明/保留 | 文件形式 | 支持的工作；缺项影响 |
|---|---|---|---|
| 当前原生模型 | 版本日期、软件版本、单位、地理位置/真北、图层/标签、组件、隐藏对象、相机；哪些是基地/周边/各方案 | SKP / 3DM / RVT / IFC / BLEND / 原生格式 | 原几何出总图、相机、剖面与表现底图；按实际工具能力读取，不凭扩展名承诺支持 |
| 预设视角（核心） | SU中已保存的Scenes/相机、视角名和对应方案；有导出JPG可一并给 | SU Scenes / JPG / PNG | 直接读已有机位；不要求用户另填一整张相机参数表 |
| 可交换模型 | 坐标变换、导出单位、对象语义、原生源哈希；不要只有一张截图 | IFC / GLB / OBJ及材质 / 可靠几何导出 | 作为原生读取不足时的明确替代；不是自动完整 BIM |
| 方案对应关系 | OP编号、中文/英文名称、每个方案的对象范围、变更日期，哪个版本作废 | 对照表 / 标签 / 文件夹 | 让图纸、指标、比较及页码引用同一方案 |
| 平面/总图 | 楼层、比例或尺寸、图框、边界、退线、入口、核心筒、功能、车行/人行 | DWG / DXF / 矢量PDF / 清晰图纸 | 整理真实技术图；平面不是仅靠效果图反推 |
| 剖面/立面 | 剖切线、标高、层高、层数、洞口、阳台、露台、结构意图 | 同上 | 表达真实高差和空间；图框文字只对所属图框有效 |
| 功能与住宅分配 | 哪层/哪块是什么功能，走道分割，户型计数方式，设备和开放空间分类 | 模型语义 / XLSX / 标注图 | 功能图、户数、功能面积；颜色相近不能作为功能证据 |
| 允许深化范围 | 可改立面/阳台/材料/景观/灯光的范围；体块、道路、邻栋、树位是否锁定 | 明确说明 | 参考转译的边界；不能把渲染变化伪称模型已修改 |

## D. 数据、分析和估算依据（已有则用，能可靠生成的由AI完成）

这一类不是全部要求用户预先提供。面积等可从可信模型提取计算；日照由适用工具按已知位置/真北等参数计算；案例与公开事实可由AI查证。功能或法定口径等不能由体块判断的内容才局部补充，不能凭空猜值。

| 输入类型 | 需要的字段 | 用途与口径 |
|---|---|---|
| 面积/经济指标 | 用地、占地、地上/地下、总建、计容、使用面积、功能分项；单位、版本、来源 | 一张事实表驱动正文、总图、比较和图注；缺项为 unknown |
| FAR/密度 | 计容或本次约定的地上口径、用地分母；占地定义 | 分别写清分子/分母；不能混用总建筑面积与地上面积 |
| 数量 | 住宅套数、分户、楼层、车位、设备等计数及对应方案 | 整数显示；连续量通常两位小数，内部计算不提前舍入 |
| 日照/环境 | 地点、真北、时区、日期、遮挡模型、分析对象、算法、计算结果 | 有方法才有数值结论；视觉太阳箭头不能替代日照计算 |
| 法规/控制 | 所在地区、文件名称/版本/条文、退线/高度/停车等适用依据 | 区分法定要求、用户设计约束与暂定假设 |
| 造价/停车估算 | 币种、时点、单价来源、面积基数、税费/地下/配套/风险的包含项和排除项 | 可比较的概念估算；不是报价或已布置停车数量 |
| 交通/配套/市场 | 位置来源、调查日期、距离方式、案例面积/产品的官方依据 | 不把直线距离写成步行时间，不把案例卖点写成项目既成事实 |

## E. 参考册与表达风格：要单独给

**这是制作类似 GIGIRI 那种参考驱动概念册的重要输入。** 请上传完整参考册，或清楚标出参考页；只说“高级一点”“像地产宣传册”不足以锁定你期待的风格。

| 参考类型 | 请指定什么 | AI 应提取什么 |
|---|---|---|
| 概念文本/方案册 REF | 哪些页喜欢、哪些不要；整册/封面/分析/总图/数据页是否同一参考 | 阅读节奏、章节结构、主图与正文关系、图文比、单页/跨页编排 |
| 排版与字体 REF | 页幅、边距、网格、留白、标题/正文/图注层级、色彩、页脚 | 可执行的版式约定与代表页，不是只采一个主色 |
| 文字逻辑 REF | 偏设计论证还是销售表达，句长、标题语气、中英关系、技术程度 | 用本项目事实重写主张、证据、设计动作与图注；不套用原项目卖点 |
| 图纸/分析 REF | 总图底色、线型、边界、图例、分析强弱、数据图风格 | 图纸表达规则；不借用参考项目的边界、指标与结论 |
| 建筑/效果图 REF | 材质、颜色、阳台、窗框、灯光、气氛、前景、视角；是否允许设计深化 | 风格转译规则及几何核对；原模型仍控制体块和场景关系 |
| 品牌 REF | 可合法使用的 Logo、名称、品牌手册、字体授权 | 只放已授权品牌，不照搬参考册的商标或字体文件 |

例如用户曾以 SILVA Gigiri brochure 指定建筑色彩、阳台、灯光、构图与气氛；这类参考应被分项记录。它不能自动覆盖本项目 SU 的体块、道路、周边建筑、绿化位置和指标。若本次只参考版式，则不扩展成建筑设计修改。详细流程见 [参考册转译](../architecture-concept-book/references/style-reference.md)。本仓库不附该第三方 brochure。

## F. 已有成果与修改意见

提供旧 PDF、可编辑源文件、相关图版/指标表，以及截图标注和文字意见。说明“必须保留 / 本次要改 / 已废弃”；截图编号要对应文件。新意见进入修订记录，不直接永久变成其他项目的规则。

## 本案例的输入与输出对照

| 来源 | 内容 | 角色 |
|---|---|---|
| 用户提供 | 已建好的SU白模型 | 核心输入，模型设计不归作AI原创 |
| 用户提供 | 已设定的机位/视角 | 核心输入，AI出图应尊重这些视角 |
| 用户提供 | 参考文本/方案册 | 核心输入，控制所指定的风格与文字逻辑 |
| AI生成 | 效果表达、模型图版、分析、文案与各页排版 | 制作输出，不应要求用户事先完成 |
| AI生成并验证 | 完整成册文件与可维护源 | 最终输出，格式依任务约定 |

设计要求、草图、用地测量、照片、原始CAD或旧册批注等若已有可补充；AI在过程中生成的指标、图版和成品不应被倒列为用户最初输入。只有尚未准备场地且任务需要时，先由场地Skill生成底座，再接收用户建筑白模型。

## 推荐的提交顺序

1. 先提供SU白模型、已有视角和参考册；用几句话说明目标，让AI清点并读取，不要求先交完整分析图文。
2. 地块还没定位/建环境时，先完成场地 Skill 的定位与模型交接；册子可同时策划叙事。
3. 固定当前方案模型、图纸与数据版本，确定参考册分别控制哪些方面。
4. 检查几张代表页是否把参考风格和项目内容结合好，再按本次授权展开。
5. 交付前一起核对图、字、数和来源，打开最终 PDF 看成品。

你不用先做一套“完美输入”。真正需要补问的是影响准确性或指定能力的缺项；其余由 AI 在现有资料范围内推进。
